# Карточка расследования: «Быстрая цепочка»

Шаблон текста карточки для [Ф5](../features.md#ф5-карточка-расследования), схема «цепочка» (`scheme: chain`).

Фронт собирает объяснение из `risk_parts.chain` и `features` группы, которые приходят в ответе graph-api.

## Данные для сборки

| Что | Откуда в ответе API | Пример |
|---|---|---|
| Уровень риска | `risk_level` | `high` |
| Итоговый риск | `risk_score` | `85` |
| Слагаемые риска | `risk_parts.chain` | `{"scheme": 55, "speed": 15, "hops": 10, "preserved": 5}` |
| Длительность | `features.span_minutes` | `11` |
| Число счетов | `features.accounts_count` | `5` |
| Оборот | `features.total_amount`, копейки | `32450000` |
| Число переводов | `transfers` группы, количество хопов | `4` |
| Дошедшая сумма | отношение последнего перевода к первому, % | `94` |

`risk_parts.chain` содержит баллы, а не исходные количества: `hops` — баллы за число переводов (хопов), `preserved` — баллы за процент дошедшей суммы.

`hops_count` — число переводов между счетами цепочки (количество переводов группы).
`preserved_percent` — процент дошедшей суммы, считаемый как `floor(сумма последнего перевода * 100 / сумма первого перевода)`. В схеме цепочки входы в кабинет не участвуют — схема выявляется исключительно по переводам.

Подписи уровня риска:

| `risk_level` | Подпись |
|---|---|
| `low` | низкий |
| `medium` | средний |
| `high` | высокий |

## Слагаемые риска

| Слагаемое из [risk.md](../schemes/risk.md) | Плейсхолдер в шаблоне | Что подставляем | Формулировка |
|---|---|---|---|
| Тип схемы «цепочка» | `scheme_line` | `risk_parts.chain.scheme` | `Тип схемы «цепочка»: +{scheme}.` |
| Скорость | `speed_line` | `features.span_minutes`, `risk_parts.chain.speed` | `Скорость: {span_minutes} мин от первого до последнего события — +{speed}.` |
| Число переводов | `hops_line` | `hops_count`, `risk_parts.chain.hops` | `Переводов в цепочке: {hops_count} — +{hops}.` |
| Дошедшая сумма | `preserved_line` | `preserved_percent`, `risk_parts.chain.preserved` | `Дошло до конца цепочки: {preserved_percent}% — +{preserved}.` |

Строки обоснования собираются по таблице; шаблон только подставляет соответствующие плейсхолдеры. `risk_parts.chain.hops` и `preserved` — баллы по [risk.md](../schemes/risk.md); в тексте подставляем фактические `hops_count` и `preserved_percent`.

Итог берётся из `risk_score`; для схемы сумма слагаемых не превышает 100, поэтому совпадает с итогом.

## Шаблон текста

```text
Риск: {risk_level_label} ({risk_score}/100)
Счетов в группе: {accounts_count}, оборот: {total_amount_rub} ₽.

Что произошло:
{scheme_summary}

Обоснование риска:
- {scheme_line}
- {speed_line}
- {hops_line}
- {preserved_line}

Итого: {risk_score}/100 — {risk_level_label}.
```

`total_amount_rub` — `features.total_amount / 100`, целые рубли с разделителем разрядов.

`scheme_summary` — короткое объяснение схемы простыми словами:

`Деньги быстро прошли через цепочку посредников (всего {hops_count} перевода): каждый следующий перевод отправлялся почти сразу после получения, а до конечного счёта дошло {preserved_percent}% исходной суммы. Это признак транзитной цепочки: средства быстро прогоняют через ряд промежуточных счетов, чтобы замести след и затруднить блокировку.`


## Сценарий `fast_chain`

Сценарий: [`backend/graph-admin-api/scenarios/fast_chain.json`](../../backend/graph-admin-api/scenarios/fast_chain.json). После запуска группа должна прийти с такими полями:

| Поле | Значение |
|---|---|
| `scheme` | `chain` |
| `risk_score` | `85` |
| `risk_level` | `high` |
| `risk_parts.chain` | `{"scheme": 55, "speed": 15, "hops": 10, "preserved": 5}` |
| `features.span_minutes` | `11` |
| `features.accounts_count` | `5` |
| `features.total_amount` | `32450000` |
| `hops_count` | `4` |
| `preserved_percent` | `94` |

Проверка чисел: `55 + 15 + 10 + 5 = 85`, уровень `high` — диапазон 75–100. `span_minutes` — 11 минут (18:03–18:14), `total_amount` — 32 450 000 копеек (83 500 + 82 000 + 80 000 + 79 000 ₽). `accounts_count` — 5 счетов, `hops_count` — 4 перевода, `preserved_percent` — 94% (79 000 * 100 / 83 500 = 94.61%).

Ожидаемый текст карточки:

```text
Риск: высокий (85/100)
Счетов в группе: 5, оборот: 324 500 ₽.

Что произошло:
Деньги быстро прошли через цепочку посредников (всего 4 перевода): каждый следующий перевод отправлялся почти сразу после получения, а до конечного счёта дошло 94% исходной суммы. Это признак транзитной цепочки: средства быстро прогоняют через ряд промежуточных счетов, чтобы замести след и затруднить блокировку.

Обоснование риска:
- Тип схемы «цепочка»: +55.
- Скорость: 11 мин от первого до последнего события — +15.
- Переводов в цепочке: 4 — +10.
- Дошло до конца цепочки: 94% — +5.

Итого: 85/100 — высокий.
```


## Сценарий `farm_and_chain` (группа «цепочка»)

Сценарий: [`backend/graph-admin-api/scenarios/farm_and_chain.json`](../../backend/graph-admin-api/scenarios/farm_and_chain.json). Вторая группа сценария («ферма») описана в [device-farm.md](device-farm.md#сценарий-farm_and_chain-группа-ферма).

После запуска группа схемы «цепочка» должна прийти с такими полями:

| Поле | Значение |
|---|---|
| `scheme` | `chain` |
| `risk_score` | `75` |
| `risk_level` | `high` |
| `risk_parts.chain` | `{"scheme": 55, "speed": 15, "hops": 0, "preserved": 5}` |
| `features.span_minutes` | `14` |
| `features.accounts_count` | `4` |
| `features.total_amount` | `5850000` |
| `hops_count` | `3` |
| `preserved_percent` | `95` |

Проверка чисел: `55 + 15 + 0 + 5 = 75`, уровень `high` — диапазон 75–100. `span_minutes` — 14 минут (18:40–18:54), `total_amount` — 5 850 000 копеек (20 000 + 19 500 + 19 000 ₽). `accounts_count` — 4 счёта (`acc-anna`, `acc-petr`, `acc-sveta`, `acc-timur`), `hops_count` — 3 перевода, `preserved_percent` — 95% (1 900 000 * 100 / 2 000 000 = 95%).

Ожидаемый текст карточки:

```text
Риск: высокий (75/100)
Счетов в группе: 4, оборот: 58 500 ₽.

Что произошло:
Деньги быстро прошли через цепочку посредников (всего 3 перевода): каждый следующий перевод отправлялся почти сразу после получения, а до конечного счёта дошло 95% исходной суммы. Это признак транзитной цепочки: средства быстро прогоняют через ряд промежуточных счетов, чтобы замести след и затруднить блокировку.

Обоснование риска:
- Тип схемы «цепочка»: +55.
- Скорость: 14 мин от первого до последнего события — +15.
- Переводов в цепочке: 3 — +0.
- Дошло до конца цепочки: 95% — +5.

Итого: 75/100 — высокий.
```
