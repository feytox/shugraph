# Бэклог: фичи вне первого спринта

---

## Ф3. Поиск и сортировка по списку

**Зачем:** быстро находить нужное, когда групп много. Это отдельная фича поверх списка, а не часть его.

**Шаги:**

1. Отфильтровать по статусу (новые, в работе, подтверждённые, отклонённые).
2. Отфильтровать по типу (устройство / адрес / цепочка / кольцо).
3. Отфильтровать по риску: отмечаются нужные уровни (низкий / средний / высокий / критический), можно несколько сразу.
4. Отсортировать: по риску или по времени.

**Что должно получиться:** все три фильтра комбинируются друг с другом; сортировка предсказуема.

**Как проверить:**

- включить фильтр «только кольца» — остались только кольца;
- включить фильтр «только новые» — нет подтверждённых и отклонённых;
- отметить в фильтре риска «высокий» и «критический» — низких и средних нет;
- переключить сортировку по времени — порядок изменился, группы не потерялись.

## Ф4. Видеть картину связей группы

**Зачем:** увидеть не оценку, а структуру: кто кому переводил, где общая точка.

**Шаги:**

1. Выбрать группу из списка.
2. Получить картину: счета группы, стрелки переводов с суммами и временем, общие устройства/адреса как точки схождения, события входа наравне с переводами (входы помечены как входы).
3. Приближать картину колёсиком, кликать по счёту, чтобы подсветить его связи, искать счёт внутри картины.

**Что должно получиться:** ключевой путь всегда один и объяснён: это самый длинный денежный путь группы; если путей несколько — остальные подписаны «ещё N путей». Общие точки показываются все: первые 3 — крупно, остальные — мелко. По картине рассказывается история: «пять счетов с одного устройства сошлись на сборщике», «деньги прошли А→Б→В→Г за 15 минут», «деньги вернулись к старту и пошли на второй круг». На 30 счетах читаемость держится подсветкой главного пути и общих точек, остальное приглушено.

**Как проверить:** открыть по одной группе каждого типа — ключевой путь и общие точки различимы, суммы, время и входы читаются; клик по счёту подсвечивает его связи.

## Ф5. Карточка расследования = отчёт на проверку

**Зачем:** одна и та же сущность: видим, почему система выбрала группу, и в том же виде отправляем дальше на проверку. Отдельного «отчёта» нет.

**Шаги:**

1. Выбрать группу.
2. Прочитать карточку: уровень риска, объяснение простыми словами, путь денег словами, ключевые счета и ключевые события, история решений по группе, снимок картины связей (вид снимка в PDF — растр или вектор — на проектирование карточки).
3. Подробный шаблон отчёта (точные формулировки объяснений) — отдельный документ, в этом RFC не описывается.
4. Отправить карточку дальше на проверку одним действием (выгрузить файл в PDF). «Дословно те же» означает: те же счета, числа, путь и причины; оформление файла может отличаться от экрана. Все сырые события доступны из карточки отдельным списком.

**Что должно получиться:** причина называется конкретно; выгруженное совпадает с увиденным по данным.

**Как проверить:**

- для каждого из 4 типов сверить текст карточки с картиной — числа совпадают;
- выгрузить карточку в PDF — те же счета, причины и путь, файл открывается и читается;
- история решений видна внутри карточки.

## Ф6. Взять в работу и вынести решение

**Зачем:** зафиксировать ответственность и итог: стоящая находка или ложная.

**Шаги:**

1. Взять новую группу в работу (статус «в работе») — обязательный шаг: подтвердить или отклонить можно только группу в работе, перескок «новая → решение» запрещён.
2. Разобрать картину и карточку.
3. Подтвердить («да, подозрительно») или отклонить («нет, объяснимо») — обязательно с комментарием, без комментария решение не принимается. Возврат назад разрешён: откатить в работу или пересмотреть решение при новой информации — каждый раз с новым комментарием в историю.
4. Увидеть, что группа ушла из новых, но находится через фильтр по статусу; решение записано в историю; состав и риск после первого решения не меняются (см. SRD-9 в [schemes.md](schemes.md)).

**Как проверить:**

- попробовать подтвердить новую без взятия в работу — не даёт;
- попробовать подтвердить без комментария — не даёт;
- подтвердить с комментарием — статус сменился, запись в истории есть, риск заморожен;
- изменить решение на обратное с новым комментарием — получилось, в истории две записи, состав и риск те же;
- отклонить другую группу — она сохраняется и находится через фильтр.

## Ф9. Проиграть отрезок времени заново

**Зачем:** показать тот же разбор ещё раз и доказать повторяемость.

**Что это НЕ такое:** мы не строим весь большой граф заново. Мы берём сохранённые события выбранного отрезка из журнала потока и заново показываем появление групп в списке — показываем, что разбор детерминирован.

**Шаги:**

1. Задать период (например, «вчера 14:00–15:00»).
2. Запустить повтор. Повтор идёт по зафиксированному срезу: события, пришедшие во время повтора, в него не входят. Номера событий те же, дублей повтор не создаёт.
3. Наблюдать: группы появляются в списке в том же порядке, с тем же составом счетов, типом, объяснением и риском, что в первый раз. Расхождение — ошибка с показом различий.

**Как проверить:** разобрать период, записать порядок групп в списке, проиграть заново — порядок, состав, причины и риск совпали.

## Ф11. Сверка с разметкой генератора — проверка «нашли / частично / пропустили / лишнее / ошибка типа»

**Зачем:** доказать, что разбор работает, на данных где ответы известны заранее.

**Шаги:**

1. Сгенерировать набор (Ф8) — известно, где 4 схемы.
2. Прогнать через разбор.
3. Получить таблицу сверки по каждому типу: нашли / частично / пропустили / лишнее / ошибка типа. «Время пересеклось» = пересекаются отрезки от первого до последнего события разметки и находки. «Ключевые счета» = все счета схемы из разметки. Один лишний счёт зачёт не валит, но помечается; два и больше лишних или неполный состав — исход «частично», с показом какие счета не сошлись; тип не совпал при совпавших счетах — исход «ошибка типа».

**Как проверить:** набор «по одной схеме каждого типа» — таблица показывает 4/4 найдено, лишних 0; набор без кольца — «кольцо: пропущено 1»; набор с лишними счетами — «частично» с перечнем расхождений.
