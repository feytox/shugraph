## Описание

У решения по группе хранится, кто его принял, а фронт может узнать текущего пользователя. Кто пользователь, graph-api узнаёт из заголовков `Remote-User`, `Remote-Name`, `Remote-Groups`, которые ставит Authelia (T-4); свою проверку пароля не делаем. Начинать можно сразу: в тестах заголовки ставятся вручную.

## Решение

- [ ] Миграция goose: у группы логин и имя автора решения. Они заполнены ровно тогда, когда заполнено `decided_at`, это проверяет CHECK, как для `decision_comment`
- [ ] Ручка решения берёт логин и имя из заголовков и сохраняет их вместе с решением. Без `Remote-User` отвечает 401, решение не сохраняется
- [ ] Карточка и список групп отдают в решении логин и имя автора
- [ ] Ручка текущего пользователя отдаёт логин, имя и группы из заголовков, без `Remote-User` отвечает 401
- [ ] Контракт `openapi.yaml` выгружен заново, `docs/entities.md` описывает новые поля
- [ ] Интеграционные тесты на тест-кейсы ниже

## Тест-кейсы

1. Решение с `Remote-User: ivan`, `Remote-Name: Иван`: в карточке и списке группы автор решения `ivan`, Иван.
2. Решение без `Remote-User`: 401, статус группы не изменился.
3. Ручка текущего пользователя с `Remote-Groups: admins,analysts`: в ответе обе группы.
