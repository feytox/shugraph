## Описание

На странице админки из GSD-37 блок, которым админ чистит данные за период по Ф13 (`docs/features.md`), чтобы перед показом начинать с чистой БД. Ручку очистки делает T-12, доступ только для админов - T-4.

## Решение

- [ ] Блок "Очистка БД" на странице админки под списком сценариев
- [ ] Поля начала и конца периода (`DateTimePicker` из `@mantine/dates`, время в UTC через `dayjs.utc()`) и переключатель "Весь период", который отключает поля
- [ ] Если начало не раньше конца, кнопка "Очистить БД" неактивна, а под полями текст ошибки
- [ ] Кнопка открывает модальное окно Mantine: выбранный период, текст "Действие необратимо. Группы с решением и их события сохранятся.", кнопки "Отмена" и "Очистить"
- [ ] "Отмена" закрывает окно без запроса. "Очистить" вызывает ручку из T-12 через `useMutation` и `@/api/client`, пока запрос идёт, кнопка в состоянии загрузки
- [ ] После успеха окно закрывается и появляется зелёное уведомление "БД очищена", при ошибке красное уведомление с `detail` из ответа
- [ ] Тесты vitest с MSW: успешная очистка, ошибка сервера, отмена без запроса, неактивная кнопка при неверном периоде
- [ ] Проверено в браузере на stage-площадке PR: после очистки группы сценария пропали из интерфейса аналитика. Скриншоты окна и результата в PR

## Не входит

Ручка очистки, проверка роли во фронте, отмена уже выполненной очистки.

## Тест-кейсы

1. Запустить `device_farm`, очистить весь период: группа пропала из интерфейса аналитика.
2. Открыть окно и нажать "Отмена": запроса нет, группа на месте.
3. Начало периода позже конца: кнопка неактивна, под полями текст ошибки.
4. Мок ручки отвечает 500: окно закрыто, красное уведомление с текстом ошибки.
