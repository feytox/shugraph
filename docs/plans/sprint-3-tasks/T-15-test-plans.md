## Описание

Тест-планы схем "адрес", "цепочка" и "кольцо" по образцу тест-плана фермы `docs/plans/test-plan-scheme-1.md` из PR #50. По ним @BarminGeorge принимает каждую схему на stage-площадке её PR до мёржа (T-7, T-10, T-8). Писать можно сразу: план опирается на правила SRD, файлы сценариев и тексты карточек, а не на код.

## Решение

- [ ] Файлы `docs/plans/test-plan-scheme-2.md`, `test-plan-scheme-3.md`, `test-plan-scheme-4.md` в том же формате, что у фермы: таблица сценариев с ожиданием и таблицы проверок с ID и пустой колонкой "Результат"
- [ ] В таблице сценариев все файлы из `backend/graph-admin-api/scenarios/`, где есть эта схема. Ожидание совпадает с `expected` в файле сценария, а риск со слагаемыми пересчитан по `docs/schemes/risk.md`
- [ ] Отдельно сценарии, где группы этой схемы быть не должно (`shared_address_three_clients`, `fast_chain_two_transfers`, `ring_single_round`), и комбинированные, где группы двух схем появляются независимо (SRD-9)
- [ ] Путь до решения: список, граф, текст карточки дословно из `docs/cards/`, решение с подписью аналитика, повторный запуск без новых групп, повторная доставка события (`204` на тот же, `409` на изменённый)
- [ ] Перед каждым прогоном БД очищается кнопкой из админки (T-13), а пока её нет - ручкой T-12 из Swagger
- [ ] Если `expected` в файле сценария расходится с правилом SRD, заведена задача на сценарий, в тест-плане это отмечено
- [ ] PR с тест-планами одобрили исполнители схем: @Khasashin (адрес, кольцо) и @mefodyvaulin (цепочка)

## Не входит

Автотесты на Playwright: по желанию, приёмка идёт по тест-плану руками.
