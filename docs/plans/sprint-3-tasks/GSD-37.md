## Описание

Страница в graph-admin-frontapp, с которой команда запускает сценарии вместо Swagger. Сейчас graph-admin-frontapp - пустой скелет без библиотек, поэтому его надо настроить так же, как graph-frontapp. Деплой админки делает T-5, вход T-4, очистку БД T-13.

## Решение

- [ ] graph-admin-frontapp настроен как graph-frontapp: те же версии Mantine, TanStack Query, `openapi-fetch`, react-router, MSW и vitest, та же тема и шрифт Golos Text. Правила из `frontend/AGENTS.md` действуют и здесь
- [ ] `pnpm gen:api` генерирует типы из `backend/graph-admin-api/openapi.yaml`, запросы идут только через `@/api/client`
- [ ] Страница берёт список из `GET /admin-api/v1/scenarios` и показывает каждый сценарий строкой: название и кнопка "Запустить"
- [ ] Над списком поле задержки между событиями `delay_s` от 0 до 5 секунд, по умолчанию 1
- [ ] Кнопка вызывает `POST /admin-api/v1/scenarios/{scenario_id}/run?delay_s=N`. Пока запрос идёт, кнопка в состоянии загрузки и повторно не нажимается
- [ ] На `202` зелёное уведомление "Сценарий <название> запущен", на ошибку красное уведомление с `detail` из ответа
- [ ] Если список пуст или не загрузился, на странице текст об этом, а не пустое место
- [ ] Тесты vitest с MSW: список, успешный запуск, ошибка запуска, ошибка загрузки списка
- [ ] Страница проверена в браузере локально и на stage-площадке PR, скриншоты в PR

## Не входит

Деплой, вход и роли, очистка БД, свой дизайн: внешний вид как у graph-frontapp.

## Тест-кейсы

1. Запустить `device_farm` с задержкой 0: зелёное уведомление, в интерфейсе аналитика появляется группа "Ферма".
2. Остановить graph-admin-api и открыть страницу: вместо списка текст об ошибке загрузки.
3. Запустить несуществующий сценарий (мок отвечает 404): красное уведомление с текстом ошибки.
